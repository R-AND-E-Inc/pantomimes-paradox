# Adopt · reconcile an existing project and migrate deliberately

## A01 · Inspect before changing process

Use the declared release for an adopted project. For an intentionally unadopted project, the resolver requires explicit `--bootstrap`; that read selects this migration guidance and is not adoption. Inventory actual instructions, working documents, approved contracts, current branch/artifacts, pending changes, open tasks/PRs where relevant, evidence, hooks, automations, and installed overlapping skills. Read relevant sources before asking for information they already contain. Do not read unrelated sensitive content.

Separate implemented reality, approved intent, historical rationale, assumptions, drift, and missing definition. Verify relevant remote state without resetting or switching active work. An open PR proves work exists, not approval. A stale state document proves neither inactivity nor lack of authorization. Reconcile user/task authorization and concurrent work before selecting the transition point. Preserve established stage/slice names and accepted decisions.

## A02 · Obligation map

For each normative obligation record its source file/revision/section and complete source text, destination, treatment, and rationale. Include trigger, exception, authority, timing, and consequence; headings alone are not evidence of preservation. Group equivalent duplicates deliberately. Classify each as preserved in shared method, retained in project policy, adapted, retired with rationale, or unresolved. Separate reusable process from product requirements, executable controls, state, and history.

For verbatim moves compare the entire declared source content, using raw-byte hashes or documented normalization. One distinctive sentence cannot prove the rest survived. For merges and rewrites review every obligation for semantic equivalence, including stricter project exceptions. Explicitly flag policy changes and losses instead of calling them zero-loss movement. Keep originals recoverable and historical snapshots reachable; a retroactive tag cannot reconstruct documents that were never committed.

## A03 · Prepare and activate separately

Prepare a versioned project profile and narrow entrypoint referencing the exact process release, existing document owners, applicable checks, deployment/approval rules, exceptions, guidance mode, and transition point, starting from `templates/project/` where the project has no equivalent. Avoid duplicating the shared playbook. Verify that the environment can resolve the declared release and that a missing release fails visibly. A profile's version string is not native pinning by itself. Preserve a tested retrieval/fallback and rollback path appropriate to the environment.

Prepare migration on an isolated branch/workspace when files are involved. Leave active main, installed global behavior, in-flight task instructions, and approved slice rules stable until authorized activation. A closed-slice boundary may be sufficient; do not require waiting for a whole long phase. Do not reset accepted reviews or repeat valid evidence just to change packaging. If authorized to activate, verify required gates and apply only the reviewed migration. Retire old editable duplicates only after the new authority is effective; retain historical access.

## A04 · Validate and recover

Validate the mapping, release resolution, references, behavioral routing, specialty dependencies, and no-loss evidence before activation. Run realistic isolated scenarios across a substantive slice, simple edit, plan-only/guide-only request, stale state, fresh review, and nonsoftware artifact as justified. Packaging validation alone does not prove behavior or speed.

Rollback restores the prior process/profile/instructions and compatible release, then starts a fresh task with that state. It does not undo accepted product work or erase history. Report actual source/candidate identities, limitations, remaining decisions, and the single next action. Never adopt, upgrade, install, merge, or change main merely because the audit found an opportunity.
